# AR試作

ブラウザだけで動くAR。アプリのインストールは不要。

**公開URL: https://gearbox00.github.io/ar/**

スマホでこのURLを開けば、いつでも使える。PCの電源もTailscaleも要らない。

| フォルダ | 方式 | ライブラリ |
| --- | --- | --- |
| `marker/` | 画像マーカー型 | MindAR 1.2.5 + A-Frame 1.5.0（CDN） |
| `place/` | 平面設置型 | Google model-viewer 4.0.0（CDN） |

## 動かすための条件

カメラを使うため、**https で配信されたページ**でないとブラウザが拒否する。
`index.html` をダブルクリックで開いても、http で開いても動かない。

httpで開いた場合、以前は MindAR の読み込みアニメーションのまま黙って止まっていた。
2026-08-30に、理由を画面に出すよう直した。

### スマホの実機で確認する（Tailscale経由・公開しない）

初回だけ、端末名を書いた設定ファイルを用意する。

```
copy tools\host.txt.example tools\host.txt
```

`tools/host.txt` に、自分のTailscaleの端末名を1行だけ書く（`tailscale status` で確認できる）。
このファイルはGitに入れない。環境変数 `AR_HOST` でも渡せる。

```
node tools/serve-https.js
```

起動すると、開くべきURLが画面に出る。同じTailscaleに入っている端末からのみ見える。
待ち受けはTailscaleのアドレスだけに絞ってあるので、同じ無線LANにいる他人の端末からは届かない。

証明書は `E:/claude_projects/<端末名>.crt` / `.key` を読む（`AR_CERT_DIR` で場所を変えられる）。
期限が切れたら `tailscale cert <端末名>` で取り直す。

ローカル配信は、公開前の変更を試すときに使う。ふだんは公開URLで足りる。

### 公開の反映

`master` に push すると、1分ほどで https://gearbox00.github.io/ar/ に反映される。

## 印刷用のPDFを作る

```
node tools/make-print.js
```

`print/markers.pdf` にA4で3枚出る（一辺 150 / 100 / 60 mm）。
各ページにQRコード、印刷時の注意、認識距離を書き込む欄が入っている。

大きさやURLを変える場合:

```
node tools/make-print.js --sizes 200,120 --url https://example.com/ar/marker/
```

**印刷するときは倍率を「実際のサイズ（100%）」にする。**
「用紙に合わせる」を選ぶと寸法が変わり、記録した認識距離が比較できなくなる。

## ① マーカーを自分で作る

外部の変換サイトを使わず、このPCの中だけで完結する。未公開の素材でも外へ出ない。

### マーカー画像を生成する

```
node tools/gen-marker.js --logo marker/assets/logo-lockup.png
```

`--logo` を渡すと、文字の代わりにその画像を中に入れる（効くのは種類bのみ）。
`--text` で文字を入れる形にもできる。

`marker/assets/generated/` に3種類（a/b/c）のPNGとSVGが出る。
`--text` で入れる文字、`--seed` で模様の並びが変わる。同じ種を渡せば同じ絵になる。

| 種類 | 見た目 | 認識点 |
| --- | --- | --- |
| a 幾何パターン型 | 図形が散った絵。デザインと認識のバランス型 | 2,043点 |
| b 高密度ノイズ型 | 細かい四角が敷き詰められた絵 | 3,284点 |
| b + ロゴ入り（現行） | bの中央に社名ロゴを入れたもの | **3,120点** |
| c 帯とロゴ型 | 線とロゴ中心。見た目は整うが点は少ない | 1,318点 |

（比較用）MindAR公式サンプルの `card.png` は588点。ただしこれは372x674と解像度が低いので、
数字の差がそのまま認識性能の差ではない。同じ1024x1024どうしのa/b/cの比較が意味を持つ。

現在 `marker/assets/marker.png` として使っているのは **bにロゴを入れたもの**。

**ロゴを入れると認識点は減る。** 実測で 3,284 → 3,120（−5%）。
ロゴの面は模様が少ないためで、大きく入れるほど落ちる。
入れたら必ず測り直し、周りの模様の密度で補うこと。

### 画像を .mind に変換する

```
node tools/compile-mind.js marker/assets/marker.png --out marker/assets/targets.mind
```

手持ちの写真やロゴでも同じように変換できる（png / jpg / webp）。
変換には1枚あたり数十秒かかる。認識点の数が段階別に表示されるので、
複数の候補を並べて比較できる。

複数のマーカーを1つの `.mind` にまとめる場合は、ファイルを並べて渡す。
その場合 `marker/index.html` の `targetIndex` で何番目かを指定する。

### 仕組み

`tools/compiler.html` が MindAR本体（`tools/vendor/`）をこのPCのブラウザで動かし、
Playwright越しに結果を受け取って `.mind` を書き出している。
公式のオンライン変換ページと同じ処理を、手元で走らせている形。

### マーカーに向かない画像

単色の面が広い、左右対称、グラデーションのみ、QRコードそのもの。

## 中身（重ねるもの）を差し替える

### ① マーカー型

`marker/index.html` の `<a-entity id="gear">` と `<a-plane id="sign">` が中身。
歯車は「黄色い円盤 + 白地 + ロゴを貼った四角い板」で組んである。

**ロゴを貼るのは四角い板（a-plane）にすること。** 円の板（a-circle）に貼ると、
模様の貼り方が放射状になって絵が歪む。実際に一度そうなった。

透明な部分から下地の色が透けるため、元の絵が白背景を前提にしている場合は、
白い円盤を1枚挟む。挟まないとロゴが読めなくなる。

### ② 床置き型 — 置くものの一覧

`place/models.json` が一覧。ページはこれを読んでボタンを並べる。
`?m=名前` を付けたURLで開くと、その項目が最初に選ばれる（共有用）。

パッケージの箱（小・中・大）は次で作る。寸法を変えるときは `--one 幅,高さ,奥行`。

```
node tools/make-box-model.js
node tools/make-box-model.js --one 0.3,0.2,0.12 --name box-custom --label "化粧箱"
```

### ② 床置き型 — 手持ちのモデルへ差し替える

```
node tools/swap-model.js 手持ちのモデル.glb --height 0.85 --label "サンプルの椅子"
```

glbを置き場所へコピーし、usdzを作り、`place/models.json` の一覧に加える。
`--default` を付けると最初に選ばれた状態になる。
`--height` はいちばん長い辺を何メートルにするかの指定。省略すると元の寸法のまま。
足元が原点に来るようそろえるので、床に置いたときに沈まない。
`--dry` を付けると、書き換えずに変換結果だけ確認できる。

**受け付けるのは glb だけ。** gltf・fbx・objは未対応。
Blenderからは「glTF Binary (.glb)」で書き出す。

### ② 床置き型 — ロゴのモデルを作り直す

```
node tools/make-logo-model.js
```

`place/assets/` に glb と usdz が出る。台座の上にロゴのコインが立つ形。
形や大きさを変えるときは `tools/model-builder.html` の `buildAndExport` を直す。

```
node tools/make-logo-model.js --radius 0.35 --thickness 0.08
```

**iPhoneの「ARで見る」には usdz が要る。** glbだけではAR表示にならない。
どちらも three.js の書き出し機能をこのPCのブラウザで走らせて作っている。
Blenderも外部サービスも使わない。

いずれも動作確認用のサンプル。実案件で使う前に差し替えること。

### 移動／回転の切り替え（2026-09-25）

操作バーの「移動」「回転」で、1本指でなぞったときの動きを切り替える。既定は「移動」（従来どおり）。

「回転」では、**触れた物だけ**を、なぞった方向へ360度どの向きにも回す（トラックボール方式）。
横になぞると縦の軸まわり、縦になぞると横の軸まわり、斜めならその中間の軸まわりに回る。
回転軸はカメラから見た向きで決めるので、物がどちらを向いていても「指の動いた方へ表面が動く」。

| 値 | 意味 |
| --- | --- |
| `ROT_PER_PX = 0.012` | 1pxあたりの回転（ラジアン）。約520pxなぞると1周 |
| `class="rotatable"` | 回す単位。歯車は `#gear`、看板は外枠 `#signWrap`（回転の中心を看板自身にするため） |

「元に戻す」で、位置・大きさ・ひねりに加えて、回した向きも最初に戻る。

**真横を向くと指が当たらなくなる問題**: 歯車は横に90度回すと薄い板になり、次になぞれなくなった
（検証で実際に起きた）。見えない当たり（歯車は球、看板は厚みのある箱。`material="visible: false"`）を付けて解決。
three.js の当たり判定は見えない物にも当たるので、描画せずに受け止められる。

**影の形**: 影の代わりの円は、歯車の表の向きに合わせて形を変える（`shadow-follow`）。
表が上なら円、斜めなら楕円、真横なら細い線。回しても丸いままだと、灰色の円盤が浮いて見えるため。
この部品は `a-scene` より前で登録しないと効かない。

### 当たり判定の仕組み

指先から3D空間へ線を飛ばし（Raycaster）、`class="grabbable"` を付けた物に当たったかを調べる。
画面のどこでも動くと「つかんでいる」感じが出ないため、当たったときだけ動かす。

当たり判定の対象は、歯車のコイン（円柱と白い円盤）と社名の看板。
**ロゴを貼った四角い板は対象から外してある。** 透明な部分まで当たり判定に入り、
実際の歯車より広い範囲で反応してしまうため。

外れたときは操作バーに「歯車か看板に触れてください」と1.6秒だけ出す。
つかんでいる間は「つかんでいます」に変わる。

中身を差し替えるときは、つかませたい物に `class="grabbable"` を付ける。

**指の操作は `#content` にだけ効かせている。** マーカーへの固定は `#target` が持つため、
動かしてもマーカーから外れない。中身を差し替えるときは `#content` の内側に置くこと。

状態は `window.__arTransform.state` から読める（検証用）。

ページを開いた・マーカーを認識した・撮った・共有した・ARで見た・商品を切り替えた、の回数を数える。
印刷会社などに「効果」を示すための材料。

| 場所 | 役割 |
| --- | --- |
| `assets/track.js` | ブラウザ側。読み込むと「開いた」を送り、`window.arTrack(種類, 補足)` で他を送る |
| `server/ar-api/track.php` | 受け取る窓口。サーバーの `public_html/ar-api/` に置く |

| `server/config.local.php` | 塩と閲覧キー。**Gitに入れない。** サーバーでは `ar-data/config.php`（public_html の外） |

### 保存しないもの

IPアドレス、氏名、端末の識別子。端末は iOS／Android／PC の3区分だけ。
連打よけのために、IPに秘密の塩と日付を混ぜたハッシュを持つ（復元できない）。
訪問の識別子はブラウザを閉じると消える（sessionStorage）。

### 受け付けの制限

1. 送り元（Origin）は設定ファイルの一覧にあるものだけ。それ以外は403
2. 出来事の種類とページ名は決め打ち。それ以外は400
3. 訪問の識別子は英数字8〜32文字。補足は英数字と `_.-` で40文字まで
4. 同じ送り元から1分に60件まで。超えたら429
5. 本文は2KBまでしか読まない

`track.js` より前に置くと、送り先を切り替えられる。手元の設定には `http://localhost:8850` を送り元として足してある。

転送時に、設定の `localhost` の行は自動で外す（本番は github.io からだけ受ける）。

### SQLiteが古い前提で書いてある

サーバーのSQLiteは3.7系。UPSERT・VACUUM INTO・ウィンドウ関数は使わない。
手元（3.39）で動いても本番で落ちるので、反映後は必ず本番で失敗経路まで打つ。

## 動かないと言われたときの調べ方

**まず `/marker/check.html` を、その端末で開いてもらう。**
接続方式、WebGL、必要なファイルの取得、カメラの起動可否を1画面で出し、
結果を文字でコピーできる。原因の切り分けはここから始める。

### アプリ内ブラウザに注意

LINE・Instagram・Facebook・X の中のブラウザから開くと、**Androidではカメラを使えないことがある。**
2026-09-01に、Samsung製Android端末で表示されないという報告があり、これを第一の候補として調べている。
判定を入れてあるので、該当する場合はARのページと診断ページの両方で警告が出る。

対処は「メニューから “ブラウザで開く” を選ぶ」。

## つまずいた点（同じことを繰り返さないために）

1. httpで開くと、MindARの読み込みアニメーションのまま黙って止まる。
   カメラが使えない理由を画面に出すようにした
2. 探しているマーカーと、画面に映した絵が別物でも、何も起きないだけで理由が分からない。
   画面の左下に「探している絵」の見本を常に出し、15秒たったらヒントを出すようにした

## セキュリティ（2026-08-30 実施）

公開前に `security-review` を実施し、4件を修正した。

1. **パストラバーサル（High）** — `serve-https.js` でURLに `..` を混ぜると配信フォルダの外が読めた。
   TLSの秘密鍵まで読めることを実測で確認。パス検査を追加し、待ち受けも
   `0.0.0.0` からTailscaleのアドレスのみへ変更した。露出した鍵は `tailscale cert` で作り直した
2. 同じ問題が `compile-mind.js` の一時サーバーにもあったため、同様に修正
3. エラー表示でURLを `innerHTML` に入れていたのを `textContent` に変更
4. Tailscaleの端末名を `tools/host.txt`（Git管理外）へ移した

修正後、攻撃側の要求7通りがすべて404になること、XSSの細工が実行されないことを実際に投げて確認済み。
